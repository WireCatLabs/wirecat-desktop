**ASK-76 · «давай использовать какие-то манифесты в CLI, типы итд. например можно генерить при билде все команды с
подкомандами и возможно access - что читается итп, плюс иметь возможность это действительно проверить по коду, что

Да: `contracts/wirecat.json`, генерируется из дерева команд с `effects` и ключами разрешений, проверяется тестом на

доказать, что код не делает лишнего, нельзя — интерфейс говорит «запрашивает», не «может только». См. IDEA-32.

**SEC-115 · Desktop запускает install-скрипты пакета (`npm install` без `--ignore-scripts`, `install.rs:204`)**
Поэтому второе подтверждение стоит **до** установки: скрипты установки и есть первый запуск. Для официальных и
списочных инструментов поведение не меняю.

**SEC-116 · cli-core пропускает команду без `effects` при уровне `readonly`**
`src/cli/early-refusal.ts` (origin/main): `level === "readonly" && effects !== undefined && writes(effects)`, хотя
`writes(undefined)` = true (cli-base `src/standards/effects.ts`). Lint (`missing-command-effects`) только
предупреждает. Сторонний CLI, забывший объявить команду, пишет при «только чтение». Проверено чтением кода, не
запуском.

**UX-69 · Причины отказа реестра и provenance не видны пользователю**
`features/tools/community.ts:8-9` — только `console.error`; при отказе provenance текст «не подтверждено, что
собрано WireCat» даже для стороннего пакета (`install.rs:312`).
