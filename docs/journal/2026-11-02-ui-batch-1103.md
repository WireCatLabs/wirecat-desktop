## 3. Находки

**FIND-189 · Запуски, которые владелец начинает из приложения, сохранялись только при ошибке**
Приложение запускает инструменты с `WIRECAT_CALLER=desktop` (`src-tauri/src/run.rs:81`). Тогда cli-core сохраняет
успешный запуск, только если в команде есть `--record` (`cli-core/src/runs/run-context.ts:35-52`, `keepsSuccess`). У
синхронизации `--record` был, а у Check (doctor), store check, backup и reset — нет. Фильтров, которые прятали бы
успешные запуски, на странице Logs нет: запрос по умолчанию скрывает только запуски без команды. Почему это всплыло
именно на Windows — предположение: там Слава пользовался только приложением, а на Linux журнал заполняют его
собственные запуски из терминала и запуски агентов. Его журнала с Windows я не видел.

**FIND-190 · Лампа агента смотрела на всю проверку, а заголовок — только на навыки**
`rowTone` (`src/features/agents/SkillTable.tsx:31`) читал итог `overall` (`src/domain/agents.ts:377`): если агент не
находит в PATH ни один инструмент, лампа красная. Заголовок (`AgentPane.tsx:58`) и строка в списке (`AgentList.tsx`)
смотрели только на `view.todo` и писали «навыки актуальны». В моке это воспроизводится так: после «Install all» у
Codex «2 things to fix», и лампа жёлтая.

**FIND-191 · «Open the run on Logs» искал запуск в старом снимке журнала, а в моке такого запуска не было**
- Страница Logs читает запуски, только когда в store ещё пусто (`src/features/logs/LogsPage.tsx:72-74`). Если Logs уже
  открывали в этой сессии, кнопка (`src/features/tools/Sync.tsx:270`) фильтровала старый снимок, где нового запуска
  синхронизации нет, и таблица была пустой. Это причина в настоящем приложении (вывод из кода, не воспроизведено на
  живом аккаунте).
- В моке id `20261103T091502Z-messages-sync-7c21e0` из `mock-sync.ts` не было в `mock-runs.ts` — то, что увидел Слава.
- Запасной фильтр «неудачные синхронизации» брал слова после выброса флагов, но значение флага оставалось:
  для tg выходило `command:"messages sync 120m"`, что не совпадает ни с одним запуском. Теперь `syncCommand` в
  `src/domain/catalog.ts` берёт слова до первого флага.

**FIND-192 · «Open terminal» в превью ничего не делал, а в приложении ошибки терялись**
- В браузерном превью `openSetup` — пустая функция (`src/platform/mock.ts:512`), а форма после неё показывала «Finish
  signing in in the terminal window» (`src/features/tools/Health.tsx:303-305`). Это то, что увидел Слава.
- В приложении три из пяти мест глотали ошибку: «Sign in» в строке аккаунта (`Health.tsx:168`) и в совете синхронизации
  (`Sync.tsx:215`) не ловили её вовсе, диалог входа делал `.catch(() => {})` и закрывался (`SignInDialog.tsx:104`).
- macOS: `osascript` только запускался (`spawn`), отказ в разрешении Automation (ошибка -1743) не был виден. Теперь
  ждём его выхода и пишем, где разрешить.
- Linux: успешный `spawn` терминала не значит, что окно открылось. Теперь терминал, который сразу вышел с ошибкой
  (например `$TERMINAL` без `-e`), пропускается. На этой машине `x-terminal-emulator` — это ptyxis; проверено
  файлом-маркером, что `ptyxis -e sh -c …` и `ptyxis -- sh -c …` оба выполняют команду.
- `open_setup` и `tailscale_terminal` были синхронными командами Tauri, то есть шли в главном потоке; теперь
  асинхронные.
- Windows прочитан, не запущен: `cmd /c start "WireCat" cmd /k "<путь>" <слова>` работает, пока в пути нет пробела вместе
  со скобками или `&` (правило кавычек `cmd /?`).
